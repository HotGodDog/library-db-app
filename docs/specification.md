# Спецификация

## Предметная область

Автоматизированная система управления библиотекой (АСУБ) предназначена для учёта книжного фонда, читателей и выдачи литературы. Система поддерживает ролевую модель доступа и автоматизирует рутинные операции библиотекаря.

## Роли пользователей

| Роль | Возможности |
|------|-------------|
| **Читатель** | Просмотр каталога, вход в личный кабинет, просмотр своих выдач, продление срока, самостоятельная регистрация |
| **Библиотекарь** | Управление книгами, читателями, выдача/приём книг, контроль просрочек, блокировка читателей, формирование отчётов, просмотр статистики |
| **Администратор** | Управление сотрудниками (библиотекарями), настройка параметров системы (сроки выдачи, лимиты продления) |

## Основные сущности

### Книга
- `book_id` — идентификатор
- `title` — название
- `author_id` — ссылка на автора
- `category_id` — ссылка на жанр
- `publisher_id` — ссылка на издателя
- `year` — год издания
- `pages` — количество страниц
- `total` — всего экземпляров
- `available` — доступно экземпляров (пересчитывается триггером)
- `is_visible` — видимость в каталоге

### Читатель
- `reader_id` — идентификатор
- `full_name` — ФИО
- `email` — email (уникальный, используется для входа)
- `phone` — телефон
- `passport` — паспортные данные
- `is_active` — активен ли аккаунт
- `is_blacklisted` — в чёрном списке

### Выдача (Loan)
- `loan_id` — идентификатор
- `reader_id` — читатель
- `book_id` — книга
- `issue_date` — дата выдачи
- `due_date` — срок возврата
- `return_date` — фактическая дата возврата
- `returned` — возвращена ли
- `extensions` — количество продлений

### Сотрудник
- `employee_id` — идентификатор
- `full_name` — ФИО
- `email` — email (уникальный, используется для входа)
- `phone` — телефон
- `position_id` — должность (Администратор / Библиотекарь)
- `is_active` — активен ли

## Бизнес-правила и ограничения

| Правило | Описание |
|---------|----------|
| Доступность книги | Книга выдаётся только при `available > 0` |
| Чёрный список | Читатель с `is_blacklisted = 1` не может получать книги |
| Просрочка | Выдача считается просроченной, если `due_date < today` и `returned = 0` |
| Продление | Максимум 2 продления на одну выдачу. Просроченную выдачу продлить нельзя |
| Срок выдачи | По умолчанию 14 дней, настраивается администратором |
| Автопересчёт | Триггеры БД автоматически обновляют `available` при выдаче и возврате |
| Видимость | Книга с `is_visible = 0` не отображается в публичном каталоге |

## Функциональные требования

### FR-1: Управление книжным фондом
- Добавление, редактирование, скрытие книг
- Учёт количества экземпляров
- Привязка к авторам, жанрам, издателям

### FR-2: Управление читателями
- Регистрация читателей (библиотекарем или самостоятельно)
- Просмотр и редактирование данных
- Блокировка/разблокировка

### FR-3: Выдача и возврат
- Выдача книги с автоматическим расчётом срока
- Приём возврата с обновлением доступности
- Контроль просроченных выдач

### FR-4: Продление
- Читатель может продлить выдачу до лимита
- Система проверяет количество предыдущих продлений

### FR-5: Поиск и каталог
- Поиск по названию книги и фамилии автора
- Просмотр доступности в реальном времени
- Фильтрация видимых книг

### FR-6: Отчётность
- Журнал операций (CSV)
- Активные выдачи (CSV, PDF)
- Статистика по фонду и читателям

### FR-7: Администрирование
- Управление учётными записями библиотекарей
- Настройка системных параметров

## Нефункциональные требования

| Требование | Значение |
