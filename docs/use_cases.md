# Use Cases

## Роли пользователей

| Роль | Описание |
|------|----------|
| **Читатель** | Пользователь библиотеки: ищет книги, оформляет выдачу, продлевает срок, отслеживает обязательства |
| **Библиотекарь** | Сотрудник: выдаёт/принимает книги, ведёт учёт читателей, контролирует просрочки, формирует отчёты |
| **Администратор** | Руководитель: управляет персоналом, настраивает параметры системы |

---

## UC-1: Управление сотрудниками

**Актор:** Администратор

**Предусловие:** Администратор аутентифицирован.

**Сценарий:**
1. Администратор открывает «Сотрудники»
2. Нажимает «Добавить библиотекаря»
3. Заполняет ФИО, email, телефон, пароль
4. Система создаёт учётную запись с ролью «Библиотекарь»
5. Система показывает подтверждение

---

## UC-2: Настройка параметров системы

**Актор:** Администратор

**Предусловие:** Администратор аутентифицирован.

**Сценарий:**
1. Администратор открывает «Настройки»
2. Изменяет срок выдачи (по умолчанию 14 дней)
3. Изменяет максимальное количество продлений (по умолчанию 2)
4. Система сохраняет параметры

---

## UC-3: Управление книжным фондом

**Актор:** Библиотекарь

**Предусловие:** Библиотекарь аутентифицирован.

**Сценарий:**
1. Библиотекарь открывает «Книги»
2. Нажимает «Добавить книгу»
3. Заполняет название, автора, жанр, год, количество экземпляров
4. Система добавляет книгу в каталог
5. Система устанавливает `is_visible = 1`

**Альтернативный сценарий (скрыть книгу):**
5а. Библиотекарь нажимает «Скрыть» — система устанавливает `is_visible = 0`

---

## UC-4: Управление читателями

**Актор:** Библиотекарь

**Предусловие:** Библиотекарь аутентифицирован.

**Сценарий:**
1. Библиотекарь открывает «Читатели»
2. Нажимает «Добавить читателя»
3. Заполняет ФИО, email, телефон, паспортные данные
4. Система создаёт учётную запись читателя
5. Система генерирует начальный пароль

---

## UC-5: Выдача книги читателю

**Актор:** Библиотекарь

**Предусловие:** Библиотекарь аутентифицирован, книга в наличии (`available > 0`), читатель не в чёрном списке.

**Основной сценарий:**
1. Библиотекарь открывает «Выдача книги»
2. Выбирает читателя из списка
3. Выбирает книгу из списка
4. Нажимает «Выдать»
5. Система создаёт запись о выдаче с `due_date = today + 14 дней`
6. Система уменьшает `available` на 1 (SQL-триггер)
7. Система показывает подтверждение

**Альтернативный сценарий (нет копий):**
4а. Книга отсутствует — система показывает ошибку «Нет доступных экземпляров»

**Альтернативный сценарий (читатель в чёрном списке):**
2а. Система показывает предупреждение «Читатель заблокирован»

---

## UC-6: Приём возвращённой книги

**Актор:** Библиотекарь

**Предусловие:** Книга числится за читателем.

**Сценарий:**
1. Библиотекарь открывает «Выдачи»
2. Находит активную выдачу
3. Нажимает «Принять возврат»
4. Система устанавливает `returned = 1`, `return_date = today`
5. Система увеличивает `available` на 1 (SQL-триггер)
6. Система показывает подтверждение

---

## UC-7: Просмотр просроченных выдач

**Актор:** Библиотекарь

**Предусловие:** Библиотекарь аутентифицирован.

**Сценарий:**
1. Библиотекарь открывает «Просроченные выдачи»
2. Система показывает список выдач, где `due_date < today` и `returned = 0`
3. Для каждой выдачи указаны: читатель, книга, дата выдачи, дата возврата, дней просрочки

**Расширение — UC-7a: Блокировка читателя**
4. Библиотекарь нажимает «Заблокировать» напротив просроченной выдачи
5. Система добавляет читателя в чёрный список (`is_blacklisted = 1`)
6. Система запрещает новые выдачи этому читателю

---

## UC-8: Просмотр статистики

**Актор:** Библиотекарь

**Предусловие:** Библиотекарь аутентифицирован.

**Сценарий:**
1. Библиотекарь открывает «Статистика»
2. Система показывает:
   - Общее количество книг
   - Количество читателей
   - Активные выдачи
   - Просроченные выдачи
   - Самые популярные книги

---

## UC-9: Формирование отчётов

**Актор:** Библиотекарь

**Предусловие:** Библиотекарь аутентифицирован.

**Сценарий:**
1. Библиотекарь открывает «Отчёты»
2. Выбирает тип: «Журнал операций» или «Активные выдачи»
3. Нажимает «Сформировать»
4. Система генерирует отчёт (CSV или PDF)
5. Система предлагает скачать файл

---

## UC-10: Поиск книг в каталоге

**Актор:** Читатель

**Предусловие:** Не требуется.

**Сценарий:**
1. Читатель открывает главную страницу («Каталог»)
2. Вводит запрос в поле поиска
3. Нажимает «Найти»
4. Система ищет по названию и фамилии автора
5. Система показывает результаты с информацией о доступности

---

## UC-11: Самостоятельная регистрация

**Актор:** Читатель

**Предусловие:** Email не зарегистрирован в системе.

**Сценарий:**
1. Читатель нажимает «Регистрация»
2. Заполняет ФИО, email, телефон, паспорт, пароль
3. Система проверяет уникальность email
4. Система создаёт учётную запись
5. Система перенаправляет на страницу входа

**Расширение — UC-11a: Вход в систему**
5. Читатель вводит email и пароль
6. Система аутентифицирует и открывает личный кабинет

---

## UC-12: Вход в систему

**Актор:** Читатель, Библиотекарь, Администратор

**Предусловие:** Учётная запись существует.

**Сценарий:**
1. Пользователь открывает страницу входа
2. Вводит email и пароль
3. Система проверяет учётные данные
4. Система устанавливает сессию
5. Система перенаправляет в личный кабинет (по роли)

**Результат по ролям:**
- Читатель → «Мои выдачи»
- Библиотекарь → «Панель библиотекаря»
- Администратор → «Панель администратора»

---

## UC-13: Просмотр своих выдач

**Актор:** Читатель

**Предусловие:** Читатель аутентифицирован.

**Сценарий:**
1. Читатель открывает «Мои выдачи»
2. Система показывает список активных выдач с сроками возврата
3. Для каждой выдачи указаны: название книги, дата выдачи, дата возврата, осталось дней

---

## UC-14: Продление срока выдачи

**Актор:** Читатель

**Предусловие:** Читатель аутентифицирован, продлений < 2, выдача не просрочена.

**Сценарий:**
1. Читатель открывает «Мои выдачи»
2. Нажимает «Продлить» напротив активной выдачи
3. Система проверяет лимит продлений
4. Система увеличивает `due_date` на 14 дней
5. Система увеличивает счётчик продлений
6. Система показывает новый срок возврата

**Альтернативный сценарий (лимит исчерпан):**
3а. Система показывает ошибку «Достигнуто максимальное количество продлений»

**Альтернативный сценарий (выдача просрочена):**
3б. Система показывает ошибку «Невозможно продлить просроченную выдачу»
